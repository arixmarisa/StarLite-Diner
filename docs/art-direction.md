## Spatial and lighting rules

- Base composition: 384×216 logical pixels (16:9). Use a 16×16 planning grid for future game tiles. This exterior is an illustration, **not** a collidable tilemap.
- All artwork is authored through Pixelorama MCP. Keep the layered `.pxo` as the source of truth. Retain PNG exports in the runtime folder.
- Use integer pixel coordinates and nearest-neighbor scaling. Runtime uses integer enlargement at 2× and above; smaller viewports fit proportionately to keep the scene readable. Never blur or rotate finished sprites at arbitrary angles.
- Global highlights face upper-left; structural cast shadows offset down-right. Window lamps and neon are local emitters. Distinguish contact shadows from cast shadows.
- Keep environmental structure, fixtures, shadows, props, and emissive accents on named layers. Do not flatten the editable source.
- Use clusters rather than random single-pixel noise. No automatic blur, soft raster gradients, or unlimited-color glow. This asset uses 20 opaque colors within its 21-swatch palette.

## Export procedure

1. Read the asset manifest in `apps/web/public/art/manifest.json` and inspect the existing Pixelorama canvas. Do not overwrite unrelated open canvases.
2. Make changes in Pixelorama MCP; maintain palette and layer roles. After creating or opening a canvas, verify its active **name, dimensions and layer count before any mutation**, including renaming, palette creation and resizing. This MCP can temporarily keep the previous canvas bound even after reporting a new canvas; explicitly select the intended tab and verify again if it differs. Do not close/discard an unrelated unsaved tab to resolve focus. On this installation, new layers can also have undersized 1×1 cels: `scale_canvas` at the intended dimensions repairs them after all layers are added. Verify that tools report drawn pixels, not clipped/skipped pixels, before proceeding.
3. Save `assets/pixelorama/starlite-diner.pxo` with all layers visible.
4. Export all visible layers as `starlite-diner.png` (static fallback).
5. Hide emission only; export `starlite-base.png`.
6. Hide all other layers, show emission only; export transparent `starlite-lights.png`.
7. Restore all layer visibility and save the source again. Export at 1× (384×216).
8. Run Pixelorama sprite QA and inspect a nearest-neighbor enlarged capture. Check silhouette, palette, alpha, shadows, and sign legibility. Composite QA for this initial image found no enclosed holes or orphan pixels.
9. Update the manifest, this guide, and the asset README when adding asset families.

Pixelorama is one shared application across chats, not an isolated canvas per agent. A local three-agent lease does not prevent another chat from changing the active project between calls. Guard drawing/export/save operations with the expected dimensions and layer names. For a native save during concurrent activity, select the exact project object and call Pixelorama's native saver with that explicit object inside one guarded script; do not rely on a prior tab switch. Reopen or inspect the saved `.pxo` to verify dimensions, populated layers, palette and tag, then compare the actual saved pixels with the native export. Keep foreign projects and their active selection untouched. Aseprite atlas dimensions/tag must also match the intended source rather than its larger review preview.

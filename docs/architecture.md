## Dependency direction

`apps/web → packages/contracts ← apps/api`

The client and API share wire schemas only. Neither application imports the other's source. The shared package has no renderer, Node API, storage adapter, or secret. Workspaces resolve it through compiled ESM exports; build it before application development and typechecking.

## API

The main-game player renderer owns optional tray-carrying presentation, not simulation state. A foot-anchored container sorts as one actor and draws rear actor → independent tray → foreground actor. One animation clock synchronizes all three frame indices. The scoped, typed `window.dinerInspect` API exposes only normal/tray visual selection after Start; route teardown removes it and invalidates retained handles. It does not modify commands, snapshots, collision, inventory, food placement or saves. `/demo` remains independent. See the [room adapter](../apps/web/src/game/front-of-house/README.md).

Local browser persistence is implemented in [the web-client save module](../apps/web/src/persistence/README.md), with three named day-ready slots, IndexedDB transactions, versioned validation, prior-checkpoint recovery and checked revisions/deletion tombstones. The [save scope](gameplay/browser-save-plan.md) and [ADR 0002](decisions/0002-browser-progress-saving.md) exclude mid-day recovery, UI and prototype wiring. Actual day/progression systems must supply a strict codec and invoke the API after a committed safe boundary; no existing route calls it yet. Simulation imports no browser APIs and Fastify remains stateless. Format 1 has no older supported format to migrate; incompatible data is preserved pending explicit future migrations.

`config.ts` validates environment at startup; `server.ts` builds the server without listening; `index.ts` owns listen/shutdown. Tests inject requests without opening ports. Versioned routes live at `/api/v1`. Liveness and readiness coincide while no external dependencies exist; split them when a real readiness dependency is introduced.

The production server also serves the built web assets from `apps/web/dist`. Client and API share one origin, which removes the need for permissive CORS. `/demo` explicitly serves the shell, and `/demo/` redirects to it. Unknown paths return JSON 404; there is no catch-all HTML fallback to hide broken asset or API requests. Fastify handles request validation errors without exposing stack traces. Helmet provides CSP and other security headers. Default request bodies are capped at 64 KiB.

The API is stateless. Do not write durable data to the container filesystem. Local-browser persistence lives behind the client repository above, with transaction/recovery tests. Server-side persistence remains separate future scope.

## Future multiplayer boundary

The user confirmed single-player v1 with architecture ready for future online co-op. The planned local world spans separate dining/kitchen views over one simulation. These physical rooms are distinct from future multiplayer session rooms. Do not build speculative authentication, WebSockets, or synchronization. If networking becomes required, keep commands and serializable state separate from display objects, establish server authority for outcomes, validate every message, define disconnect/reconnect semantics, and cap rates/payloads before exposing a transport.

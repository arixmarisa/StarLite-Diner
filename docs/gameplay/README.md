## Core connection

`Start day → breakfast service → dinner service → close arrivals → resolve active parties → end-of-day report → mandatory cleanup → next-day ready`

Confirmed end-of-day addition: a small right-side **Upgrades** button opens the station upgrade menu. Proposed access covers report and cleanup; purchases are optional and cleanup remains required. Grill auto-flip and auto-pickup are user examples. The [upgrade catalog](upgrades.md) records possibilities and pending prices/unlocks/automation details. This request authorizes documentation only.

Within service:

`Auto-seat party → ask for drinks → record ticket → cook/pour → tray delivery → menu decision or drink-only completion → record/cook/deliver food → whole party finishes → collect payment/tip and dirty dishes → put dishes away → make seating reusable`

The brief establishes the main sequence. Closing/draining rules, exact completion guards, and seating reuse are proposals detailed in the flow document. Avoid interpreting this short outline as a replacement for its edge cases.
